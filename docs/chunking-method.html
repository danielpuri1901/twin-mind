Is this how the frontier does it? Yes - with one knob

Our choiceFrontier verdict
Window ~400 tokensthe sweet spot - 400-512 tokens is the recommended default (Chroma, NVIDIA, Firecrawl)
~25% overlapa touch high - norm is 10-20%; Chroma found 50% is the *worst* (near-duplicates crowd top-k). A knob to test with retrieval_eval.
Contextual embeddingliterally Anthropic's Contextual Retrieval - "the largest single improvement, +5-7 pts, 90% of the way to optimal." Your +6.7 reproduced it.
Semantic-segment + summarize for CC/meetingsexactly the guidance: semantic/LLM chunking wins on mixed-topic long-form (transcripts, heterogeneous sources); recursive-first then semantic only where topics don't align with structure
Hybrid vector + BM25 (RRF)Anthropic's Contextual BM25 - "embeddings + BM25 beats embeddings alone"
Measure on your own corpusthe meta-rule everyone repeats - and you already do it (retrieval_eval, the earned +6.7)

One caveat the field keeps stressing: semantic chunking only beats fixed-size on genuinely mixed-topic content (NAACL 2025). Your Claude Code sessions - one terminal, many topics - are exactly that case, so it's the right call there and not for the clean chat threads.
