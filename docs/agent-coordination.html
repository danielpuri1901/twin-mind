How Twin's agents coordinate

One rule: agents never talk to each other - everyone reads and writes one shared board (files).

How to read it: there is not a single arrow between two agents - that's the whole design. Each agent wakes up on its own schedule, reads what it needs from the board, does its one job, writes its result back, and exits.
📐 The one law of the board: every file has exactly one writer; everyone else only reads. (Both outages this week - the recap race and the Granola token death - were violations of this law.)
Examples you've lived:
  • meetings → prep + recap: the Wispr Flow ingester writes meetings into the corpus; prep and the weekly recap just read the corpus. They never meet.
  • brief → tomorrow's brief: covered-topics lists in state/ - an agent leaving notes for its future self.
  • us → brief: we write a learning into the CHANGELOG; next morning the brief teaches it to you.
  • brief → the eval gate: every real morning is saved as a fixture; the gate replays it before anything ships.
What this pattern is called: a blackboard architecture (1980s AI classic, now the 2025-26 industry standard for decoupled agents - Anthropic, Manus, and the FS-Researcher paper all converged on "files as the coordination medium").
🧭 Hermes is two things, not an orchestrator: the plumbing (Telegram gateway + message history + delivery - pipes every agent uses) and one peer agent (the chat twin, for genuinely ambiguous work). The scheduled jobs are deterministic pipelines with at most one constrained LLM call. The rule: agent loop where the task is ambiguous · pipeline where the task is predictable.
