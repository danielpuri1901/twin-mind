The Eval Flywheel

How production teams build an agent you can trust: engineer as much as possible into checkable code, keep a calibrated judge only for the subjective residue, and let real usage feed a golden set that never stops growing.

Pick a grader per failure mode

Not per section - per failure mode. Use the strongest one the thing allows.

  1. Code check (verifiable / RLVR) - the answer is checkable or has ground truth. Runs on 100%. e.g. schema, date, quote-is-real, triage vs gold label
  2. Behavioral outcome - did they act / did it persist. Objective, sparse, delayed. e.g. "did I actually use this insight" (GitHub Copilot: acceptance + retention)
  3. Calibrated LLM judge - subjective residue only. Binary + written critique. Trust only when aligned to your labels. e.g. insight quality, coach grounding (= RAGAS faithfulness)
  4. Thumbs up/down - weakest, biased, gameable, sycophantic. A side channel, never the anchor.

Three layers (all hang off tracing)

  1. Offline gate - CI on every change: run the golden set, block regressions like a failing unit test.
  2. Online monitoring - score a sample of live traffic, alert on drift.
  3. Flywheel - a bad live run becomes a labeled golden case + a judge correction. Every fixed failure is a permanent test AND a sharper judge.

Schneider Electric & Rippling run this exact 3-layer shape in production on LangSmith.

The one hard rule (learned the painful way): never build an eval dataset by scraping mixed runs through the UI - construct it in code with one fixed schema. UI-scraped mixed runs gave the judge missing fields → it graded blind → bogus 0.37 alignment. Rebuilt in code with a fixed {ai_advancements} → {insight_is_real} schema → real 0.94. Datasets are code. Label in the UI; build, measure, and gate in code.

Grounded in what frontier / prod systems do

  • Push everything checkable to code - "Decompose First, Judge Last": a judge tells you it feels worse; a code check is a stack trace. Anthropic: deterministic graders where possible, LLM where necessary.
  • Verifiable rewards beat preference - frontier RL moved from RLHF (human thumbs → sycophancy) toward RLVR (checkable outcomes). Make the reward checkable and it can't be gamed.
  • Binary + critique, calibrate to a human - Hamel / OpenAI / LangChain converge: never 1-5 scales, one judge per failure mode, target >90% agreement measured as precision/recall (not raw agreement), calibrate against your labels.
  • Behavior > stated preference - Copilot: acceptance + code persistence predicts value better than ratings. CJE: calibrate a cheap judge against a small oracle slice or it can invert your rankings.
  • Bootstrap, then let usage teach you - you can't predict every failure mode; ship cheap checks + obvious judges + dogfooding, and the flywheel folds in the rest. You are user-zero.
