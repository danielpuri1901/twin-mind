# Twin Mind - project rules

A personal AI twin + life-coach that learns from Daniel's own data, runs on AWS, stays human-in-the-loop, and gets sharper as the corpus grows.

Design: `docs/2026-06-30-twin-mind-design.md` · Build plan: `docs/gameplan.md` · Data sources: `docs/ingestion-plan.md`

## Ground truths (locked - do not relitigate without a reason)

- **Agent:** Hermes Agent (Nous Research, MIT, Python), run as a managed container. Provides memory, skills, cron, MCP, and Discord natively.
- **Inference:** Claude via AWS Bedrock (per-token, paid by AWS credits). Tiered: Haiku 4.5 for triage/classify, Sonnet 4.6 for drafting, Opus only for hard reasoning.
- **Region:** eu-west-1 home, EU geo inference profiles (`eu.anthropic.*`) - keeps personal-data processing in-geography per the Bedrock geographic-CRIS doc; accepted possible ~10% premium over global.
- **Caching (was OFF post-Converse-migration; FIXED + verified 2026-07-16):** the `bedrock_converse` path sent NO `cachePoint`, so every turn re-paid full input (2026-07-03 "it works" claim was stale). Live probe proved it: the shape the agent sent returned `cacheReadInputTokens: 0` on repeat; adding a `cachePoint` wrote then read the cached tokens at ~1/10 rate. **FIX APPLIED 2026-07-16:** patched `build_converse_kwargs` (agent/bedrock_adapter.py) to append a `cachePoint` to the system block when the system prefix is large (>6000 chars, safely over the cache minimum). Verified: big-system caches (call 2 cacheRead>0), small-system skips the checkpoint, both return valid output. **CAVEATS:** (1) it's a LOCAL patch to the Hermes framework, not our repo - backup at `bedrock_adapter.py.bak-cachepoint`; RE-APPLY after any Hermes update. (2) Activates on the next gateway RESTART (the running process holds the old code in memory). (3) Caches the system prefix only; message-level (growing-history) caching is a follow-up. Corollary still live: long Telegram sessions grow fat, so a compaction policy is worth having.
- **Observability + evals:** Langfuse Cloud free tier. NOT self-hosted (self-hosting runs ~$150+/mo idle - a proven cost trap).
- **Langfuse visibility (Daniel's rule, 2026-07-15):** everything the system produces that Daniel would inspect must ALSO reach Langfuse, not just a local file - eval datasets (briefs-sent, brief-verdicts, prep-verdicts, inbox-decision-answers, ...), judge scores, model bake-off / experiment runs, and every agent cron run's trace. Local files stay the source of truth (EU-residency, own-the-crown-jewels); Langfuse is the human-facing mirror for Daniel. A result that exists only as local JSONL and never appears in Langfuse is NOT done. Any new eval script or agent must wire its output to Langfuse as part of shipping. MECHANISM: `evals/push_to_langfuse.py` mirrors the local JSONL datasets into Langfuse Datasets (idempotent; item ids namespaced by dataset because Langfuse ids are unique per project). STATUS 2026-07-15 (verified): traces + scores already write fine (auth ok; the brief cron trace lands - the earlier "broken" read was a probe using the wrong env-var names `LANGFUSE_*` instead of the stored `HERMES_LANGFUSE_*`, plus a stale Jul-8 OTel context warning that does not stop delivery). Datasets now mirrored: inbox-decision-answers, brief-verdicts, prep-verdicts, qa-answers, briefs-sent. REMAINING: run push_to_langfuse.py automatically (nightly cron or post-eval) so Langfuse stays current without a manual run; it is presently run by hand.
- **Corpus, two-tier (approved 2026-07-02):** raw data stays on the Mac, encrypted, NEVER pushed or synced anywhere. Only the derived working set (wiki/ + corpus.db + normalized/) deploys, point-to-point over SSM, to the box's encrypted EBS. Nothing corpus-related ever touches S3, git remotes, or third-party storage. Common format: one record = `{source, date, who, text}`.
- **Active window (2026-07-02):** the full corpus is memory (recall, facts, timeline); only the rolling last ~12 months defines voice exemplars, professional register, tendencies, coach baselines, and scorecard pairs. Older eras are context, never template.
- **Corpus versioning:** ~/twin-corpus is a LOCAL-ONLY git repo (raw/ untracked; normalized/ + wiki/ snapshotted per refresh; pre-push hook hard-fails so it can never leave the machine).
- **Retrieval contract:** all corpus access goes through the `corpus-search` CLI (shimmed on PATH; `shared/corpus_search.py`: query -> JSON lines). Backends: FTS5 + Cohere-multilingual-v3 embeddings in sqlite-vec. **Default mode: hybrid** (bake-off verdict 2026-07-03); drafting retrieval is audience-conditional. Skills and evals call only the contract.
- **Build order:** validate the whole twin ON THE MAC (index, wiki, gold pairs, local Hermes vs Bedrock) before creating any AWS resource beyond CLI auth + Bedrock access. AWS is lift-and-shift of a known-good config.
- **Channel (final, 2026-07-02):** Telegram = interactive home (official Bot API - stable for years, zero ban risk, free proactive, not blocked at work). Morning brief = real email send via Daniel's Gmail (SMTP app password, send-only; NEVER the Hermes email gateway adapter on his personal inbox - it marks all mail seen and polls). Discord dropped (blocked at work); WhatsApp Baileys optional later as a parallel channel (unofficial bridge: re-pairing + ban risk documented).
- **Eval-first:** build the scorecard before tuning anything. Nothing "improves" the twin unless it beats the scorecard.
- **Online-eval doctrine (2026-07-12):** we follow `docs/eval-doctrine.md` (two LangChain articles translated to n=1): deterministic checks on everything, calibrated judges, verdicts->dataset within a day, weekly review queue.
- **Evals measure the ACTUAL job (Daniel's order, 2026-07-14, after drafting-gold nearly caused a bad model swap):** before any eval result informs a decision, name the production job it measures. Datasets for cancelled or parked jobs are DELETED, not repurposed as proxies. Model decisions require the target agent's own-job benchmark (the brief's = evals/run_brief_bench.py on real prefetch fixtures, judged by Daniel-calibrated judges). The regression suite qualifies judgment only - never composition.
- **Per-agent golden datasets (canon, 2026-07-24):** each agent's eval measures its OWN job against its OWN golden set, NOT a shared/general gold. **brief -> `morning-brief`** (LangSmith dataset in the twin-mind workspace: the real-morning prefetch inputs from `~/twin-corpus/datasets/brief-inputs/`; Daniel labels the composed briefs good/bad, and those labels calibrate the one grader). retrieval -> `corpus-qa`. background-prep -> `prep-dossier-verdicts`. weekly-recap -> TODO. The old general gold (`scorecard-pairs`, `gold-set`, `pipeline/gold/*`) is RETIRED - it was corpus voice/QA pairs, not a per-agent-job measure.
- **Eval workflow: label in the UI, build and measure in CODE (canon, 2026-07-27).** The LangSmith UI is for the human-in-the-loop only: labeling in annotation queues, exploring traces, tuning a judge prompt in the Evaluator Playground, watching dashboards and alerts. Everything mechanical is CODE (SDK): building datasets, running experiments, computing metrics (precision/recall, alignment), the ship gate, bulk queue/dataset ops. HARD RULE: never build an eval dataset by scraping mixed runs through the UI - construct it in code with ONE explicit fixed schema. (The 2026-07-26 lesson: UI-scraped mixed run types gave inconsistent schemas, the insight judge then graded blind on missing fields, and alignment read a bogus 0.37; rebuilt in code with a fixed `inputs={ai_advancements}` / `outputs={insight_is_real}` schema and it read the real 0.94.) Datasets are code: versioned in the repo, gated. Grader per failure mode, best to worst: code check (checkable or ground-truth, run on 100%) > behavioral outcome (did Daniel act / did it persist) > calibrated LLM judge (subjective residue only; binary + critique; measure precision/recall vs Daniel's labels, red-team with adversarial negatives; trust only when aligned) > thumbs (weakest, never the anchor). One judge per failure mode, never a blended "overall quality" score. The domain-expert-is-ground-truth premise holds only where Daniel IS the expert (scope `insight_is_real` to "useful to me", not "factually a real advance"); factual truth needs a source-check, not a judge.
- **Ship gate (mechanized 2026-07-08):** no change to skills, SOUL, tools, prompts, or model tier ships to the box without `evals/eval.sh` green (triage regression at 100%). Baseline: 9/9 PASS on first run, 2026-07-08.
- **Autonomy by reversibility:** act autonomously on read / search / research / draft; require human approval for send / spend / commit / anything irreversible.
- **Cost discipline:** credits go to compute (Bedrock + a one-off GPU for the fine-tune), not storage. Stop GPUs the moment a run ends. No idle managed services.

- **Bottleneck rules (stepback 2026-07-14):** when a human input blocks the critical path >24h, Claude's next session opens with ONE consolidated ask (with time estimate) and builds nothing further on the blocked chain. Daniel timeboxes human-input tasks like meetings, or explicitly defers so work re-sequences.


## Repo law: one folder per agent (2026-07-14)
The repo is organized by product: `agents/<name>/` holds EVERYTHING that agent is (SKILL.md,
OPERATIONS.md, its tools/, its JOB.md). `shared/` only for things two+ agents use (SOUL, corpus
contract). `evals/` = the gate. `pipeline/` = Mac-only data prep. Nothing gets built outside an
agent folder without naming which agent it serves. When in doubt: fewer files, flatter, closer
to the agent.

## Engineering rules - how we make decisions here

- **Ground every AWS design decision in the official AWS docs, and cite the doc.** Never decide infrastructure from memory.
- **Never hallucinate or invent** a service, API, flag, price, or limit. If unsure, look it up before writing it down.
- **"Better" requires proof.** Before choosing X over Y, show the real comparison - cost, docs, tradeoffs. "I assume there's a better way" is not a reason; prove it or don't claim it.
- **Think it through.** No unexamined assumptions on anything that costs money or is hard to reverse.
- **Deterministic-by-default; enforce structured outputs.** Compute every fact in code and inject it into the prompt - the model judges and writes, it never computes dates, counts, or lookups (the 2026-07-24 brief "Friday 25 July" date-guess is why: the one fact not injected got hallucinated). When the model MUST return structured data (a verdict, score, classification, extraction), enforce it with the model's own structured-output mechanism - Bedrock Converse forced tool-use + a JSON schema, validated (Pydantic where useful). NEVER prompt-for-JSON-then-regex-parse, and NEVER silently default on a parse failure (`except: return False` corrupts results invisibly). If a decision comes from the LLM, its shape is enforced, not scraped.
- Prose and commit conventions follow the global `~/.claude/CLAUDE.md` (no em dash, sentence-per-line in long markdown, no auto co-author on commits).
