# Twin Mind - project rules

A personal AI twin + life-coach that learns from Daniel's own data, runs on AWS, stays human-in-the-loop, and gets sharper as the corpus grows.

Design: `docs/2026-06-30-twin-mind-design.md` · Build plan: `docs/gameplan.md` · Data sources: `docs/ingestion-plan.md`

## Ground truths (locked - do not relitigate without a reason)

- **Agent (AMENDED 2026-11-06):** Chat runs on self-hosted Letta Code 0.34.41, on the same Telegram bot, as `twin-chat.service` under its own OS user `twin-chat` with the local backend. The model is Sonnet 5.5. Daniel chose Letta because chat exists for memory and for thinking out loud. Hermes Agent (Nous Research, MIT) ran chat, cron and delivery until then. It is stopped and disabled but still installed for rollback, and it is deleted only when Daniel confirms. Scheduled jobs are no longer agents: systemd timers run plain scripts (see `infra/systemd/`). `agents/chat/mods/twin_mind.ts` is the only bridge to Letta (auto-retrieval on `turn_start`, the tools, the chat log, the shell policy). It is a mod because Letta's prompt and stop hooks fire only in its terminal UI. `shared/chat_log.py` is the only contract the corpus ingest and the weekly recap have with the chat harness.
- **Inference (AMENDED 2026-10-22, Daniel's call: Anthropic API credits pay for inference, AWS credits for infrastructure; re-checked 2026-11-06):** Claude via the Anthropic API, through `shared/claude.py`. The key is the Secrets Manager secret `aws-inference`. Scripts read it through the instance role at run time. For chat, root reads it at service start and writes it to `/run/twin-chat`, a tmpfs, so it is never on disk (`infra/bin/twin_chat_write_key.py`). Tiering: Haiku 4.5 for triage/classify and compression, Sonnet 5.5 for drafting and chat (since 2026-10-23), Opus only for hard reasoning. Embeddings (Cohere) and rerank stay on Bedrock. The Anthropic API path is not EU-pinned.
- **Region:** eu-west-1 home. Bedrock embeddings stay in-geography. (Before 2026-10-22, Claude inference also used EU geo inference profiles `eu.anthropic.*`; it no longer does, see Inference.)
- **Caching (CORRECTED 2026-11-06):** The Bedrock `cachePoint` patch to the Hermes adapter (2026-07-16) is gone with the Bedrock path and Hermes. `shared/` sends no cache markers. Prompt caching for chat is whatever Letta does, and nobody has verified it. Long chat sessions still grow, so watch token use.
- **Observability + evals:** Langfuse Cloud free tier is the only trace store. LangSmith was removed 2026-10-28. NOT self-hosted (self-hosting runs ~$150+/mo idle - a proven cost trap). Chat traces reach Langfuse through `pipeline/ingest_twin_chat.py`.
- **Langfuse visibility (Daniel's rule, 2026-07-15):** everything the system produces that Daniel would inspect must ALSO reach Langfuse, not just a local file - eval datasets (briefs-sent, brief-verdicts, prep-verdicts, inbox-decision-answers, ...), model bake-off / experiment runs, and every agent cron run's trace. Local files stay the source of truth (EU-residency, own-the-crown-jewels); Langfuse is the human-facing mirror for Daniel. A result that exists only as local JSONL and never appears in Langfuse is NOT done. Any new eval script or agent must wire its output to Langfuse as part of shipping.
- **Corpus storage (AMENDED 2026-09-23, supersedes the two-tier rule of 2026-07-02):** the corpus lives in S3, all tiers including raw. Required controls, not optional: a customer-managed KMS key, versioning on, block-public-access on, a bucket policy denying non-TLS requests and every principal outside the account, and server access logging to a separate bucket. Daniel made this call after being told that the derived tier holds verbatim message text and that raw includes health, legal, identity and financial documents; uploaded objects are permanently outside the Mac even after deletion. The superseded rule kept raw on the Mac and forbade S3 entirely; it was replaced because the only live copy sat on one EBS volume with DeleteOnTermination true and zero snapshots. Common format is unchanged: one record = `{source, date, who, text}`.
- **Episodic memory (CORRECTED 2026-09-28, MOVED 2026-11-06):** Chat messages reach the corpus as the `twin-chat` source through `pipeline/ingest_twin_chat.py`, on a 30-minute timer, idempotent on a stable message id. Memory does NOT depend on a session ever ending. Since 2026-11-06 the ingest reads the chat log `/var/lib/twin-chat/chat-log.jsonl`, which the `twin_mind.ts` mod appends (`shared/chat_log.py`). Before, it read Hermes `state.db`. The agent's own memory is Letta's git-backed MemFS with dreaming every 25 steps: `persona.md` and `human.md` load every turn; `people/`, `topics/`, `learning/`, `reference/` and `skills/` load on demand. The wiki moved there at cutover. The corpus stays in `~/twin-corpus` and is searched through `corpus-search`. The Hermes `twin-episodic` plugin and its day-start block are retired with Hermes. Long-term memory must never be the context window: see `docs/2026-09-23-twin-memory-v2-design.md`. (History: a 04:00 gateway restart once cut the day, assuming a restart closes the session. It does not, so that timer was deleted 2026-09-28.)
- **Active window (2026-07-02):** the full corpus is memory (recall, facts, timeline); only the rolling last ~12 months defines voice exemplars, professional register, tendencies, coach baselines, and scorecard pairs. Older eras are context, never template.
- **Corpus versioning (AMENDED 2026-09-23):** ~/twin-corpus stays a git repo for local history (raw/ untracked; normalized/ + wiki/ snapshotted per refresh). The old rule also said a pre-push hook hard-fails "so it can never leave the machine"; that clause is retired, because the corpus now syncs to the S3 bucket named above. The hook stays only as a guard against pushing the corpus to a CODE remote such as GitHub, which is still never allowed.
- **Canonical corpus (2026-09-29):** `~/twin-corpus/normalized-canonical/` is the authoritative record tree, exported FROM the index by `pipeline/export_canonical_corpus.py` before every 15-minute sync, with a MANIFEST.json carrying a per-source count and checksum. It exists because the index was not reproducible from any input tree: reconciled by text, `normalized-windowed-ctx/` covered six sources at 96-100%, `normalized/twin-chat.jsonl` covered 39.7%, and all 526 `meeting` records matched no file at all. 1,679 records existed only inside vectors.db, so the jsonl "durable copy" was not one. Rebuild with `build_index.py --inputs ~/twin-corpus/normalized-canonical/*.jsonl` and `embed_corpus.py --inputs ... --out ...`; verified as an exact round trip, 8,396 records, every source matching. NEVER rebuild from `normalized/*.jsonl`: that glob yields 29,812 records and re-ingests the purged gmail noise. The older trees are kept as history and are not inputs.
- **Retrieval contract:** all corpus access goes through the `corpus-search` CLI (shimmed on PATH; `shared/corpus_search.py`: query -> JSON lines). Backends: FTS5 + Cohere-multilingual-v3 embeddings in sqlite-vec. **Default mode: hybrid** (bake-off verdict 2026-07-03); drafting retrieval is audience-conditional. Skills and evals call only the contract.
- **Build order:** validate the whole twin ON THE MAC (index, wiki, gold pairs, local Hermes vs Bedrock) before creating any AWS resource beyond CLI auth + Bedrock access. AWS is lift-and-shift of a known-good config.
- **Channel (final, 2026-07-02; amended 2026-11-06):** Telegram = interactive home (official Bot API - stable for years, zero ban risk, free proactive, not blocked at work). Letta now serves that bot; `shared/telegram_send.py` sends scheduled messages on the same bot and never polls. Morning brief = real email send via Daniel's Gmail (SMTP app password, send-only, recipient-locked). Discord dropped (blocked at work); WhatsApp Baileys optional later as a parallel channel (unofficial bridge: re-pairing + ban risk documented).
- **Eval-first:** build the scorecard before tuning anything. Nothing "improves" the twin unless it beats the scorecard.
- **Eval reset (Daniel's call, 2026-11-06):** the LLM judges, benches and calibration sets are gone because they flagged nothing anyone acted on. A new check must measure a real outcome or a silent failure, run without a person or block a build, reach Daniel on Telegram or stop the build, and fail once on purpose first. Details and what remains: `docs/eval-doctrine.md`.
- **Evals measure the ACTUAL job (Daniel's order, 2026-07-14, after drafting-gold nearly caused a bad model swap):** before any eval result informs a decision, name the production job it measures. Datasets for cancelled or parked jobs are DELETED, not repurposed as proxies. The regression suite qualifies judgment only - never composition.
- **Ship gate (mechanized 2026-07-08):** no change to skills, SOUL, tools, prompts, or model tier ships to the box without `evals/eval.sh` green (triage regression at 100%). `infra/deploy_box.sh` enforces it: the script runs the gate on a separate copy and stops if the gate is red. Baseline: 9/9 PASS on first run, 2026-07-08.
- **Autonomy by reversibility:** act autonomously on read / search / research / draft; require human approval for send / spend / commit / anything irreversible.
- **Cost discipline:** credits go to compute (inference + a one-off GPU for the fine-tune), not storage. Stop GPUs the moment a run ends. No idle managed services.

- **Bottleneck rules (stepback 2026-07-14):** when a human input blocks the critical path >24h, Claude's next session opens with ONE consolidated ask (with time estimate) and builds nothing further on the blocked chain. Daniel timeboxes human-input tasks like meetings, or explicitly defers so work re-sequences.


## Repo law: one folder per agent (2026-07-14)
The repo is organized by product: `agents/<name>/` holds EVERYTHING that agent is (SKILL.md,
OPERATIONS.md, its tools/, its JOB.md). `shared/` only for things two+ agents use (SOUL, corpus
contract). `evals/` = the gate. `pipeline/` = Mac-only data prep. Nothing gets built outside an
agent folder without naming which agent it serves. When in doubt: fewer files, flatter, closer
to the agent.

## Engineering rules - how we make decisions here

- **Ground every AWS design decision in the official AWS docs, and cite the doc.** Never decide infrastructure from memory.
- **Never hallucinate or invent** a service, API, flag, price, or limit. If unsure, look it up before writing it down.
- **"Better" requires proof.** Before choosing X over Y, show the real comparison - cost, docs, tradeoffs. "I assume there's a better way" is not a reason; prove it or don't claim it.
- **Think it through.** No unexamined assumptions on anything that costs money or is hard to reverse.
- **Deterministic-by-default; enforce structured outputs.** Compute every fact in code and inject it into the prompt - the model judges and writes, it never computes dates, counts, or lookups (the 2026-07-24 brief "Friday 25 July" date-guess is why: the one fact not injected got hallucinated). When the model MUST return structured data (a verdict, score, classification, extraction), enforce it with the model's own structured-output mechanism - `shared/structured.py` (Anthropic structured outputs + a Pydantic schema, validated). NEVER prompt-for-JSON-then-regex-parse, and NEVER silently default on a parse failure (`except: return False` corrupts results invisibly). If a decision comes from the LLM, its shape is enforced, not scraped.
- Prose and commit conventions follow the global `~/.claude/CLAUDE.md` (no em dash, sentence-per-line in long markdown, no auto co-author on commits).

## Current state

- Production agents: morning brief, meeting prep, weekly recap, and interactive chat.
- Chat is a long-running Letta service. The brief, the watchdog and the meeting-prep poller are systemd timers that run scripts (`infra/systemd/`) through `shared/telegram_send.py --run`. They use the venv `~/.twin-mind/venv`, pinned in `infra/box-requirements.txt`.
- Env, state and tokens live in `~/.twin-mind`. Some of them are symlinks into `~/.hermes` until Hermes is deleted.
- Meeting prep is code, not an agent: `agents/background-prep/tools/compose_prep.py` does code research plus two model calls that have no tools.
- The twin-chat user cannot reach the instance role (iptables on the metadata address), `.env` or the corpus. Its tools run through a narrow sudo rule (`infra/sudoers/twin-chat`). It has no shell outside its memory repo, `web_fetch` needs Daniel's approval each time, Letta's own domains are blocked in `/etc/hosts`, and the mods and governed skills are immutable.
- Backups: `shared/corpus_sync.py` refuses to upload when any snapshot fails, and it also backs up `/var/lib/twin-chat`.
- A deploy is `infra/deploy_box.sh`, run on the box. `~/super-project` is a git checkout of the public repo. `infra/check_box.sh` proves that the checkout is clean and at `main`, and that installed copies (systemd units, sudoers, Letta mod and skills, `twin-chat-letta`) equal the repo. The deploy script does not install those copies.
- Runtime uses a private AWS host reached through SSM.
- Private identifiers plus live operational notes belong in ignored CLAUDE.private.md.
- Read CLAUDE.private.md when it exists locally.
